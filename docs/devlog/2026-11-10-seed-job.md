# Remove POST /upload and Add an Opt-in Seed Job

## Goal
Part 2 of Issue #40: replace the unauthenticated, destructive `POST /upload`
with a controlled seed. Part 1 (backup and restore) is Draft PR #54 and is not
on this branch; parts 3 and 4 come later. kind-learn was not touched.

## Features implemented
- `e0200c0` feat(backend): `seed.js` with `seedData` in `app/postgresql.js`
  and `app/redis.js`. One transaction under an advisory lock, table created
  only if missing, insert only into an empty table with `ON CONFLICT DO
  NOTHING`; Redis `SET NX`; exit 1 on failure.
- `9097105` fix(backend): `/upload` route and `importData` removed; a test
  asserts POST/GET/PUT `/upload` return 404.
- `121a84f` feat(chart): `templates/seed-job.yaml`, NetworkPolicy
  `minishop-seed`, `seed.enabled: false`, `seed.resources`, schema entries,
  shared helper `minishop.dataEnv`. Default renders are byte-identical;
  `validate-helm.sh` also renders with the seed on.
- `1beb098` fix(scripts): `validate-app.sh` requires items (seed hint
  otherwise), asserts POST `/upload` is non-2xx and items are unchanged, and
  refuses unless every backend Pod runs a ghcr MiniShop backend build that is
  not `e87390d3...`, `44a87d71...` or `599480a8...`. Superseded by the review
  fix below.
- Review fix, `fix(scripts): check seed.js before the upload probe`:
  - Positive guard: every backend container's requested image and running
    image ID must match
    `^(docker-pullable://)?ghcr\.io/thanhdu-hcmus/minishop-backend@sha256:[0-9a-f]{64}$`
    (spec without the prefix), or the script exits 1.
  - `kubectl exec ... test -f /usr/src/app/seed.js` decides whether the POST
    probe runs. A failed exec exits 1.
  - A pre-#40 image (no `seed.js`, or one of the four published pre-#40
    digests) prints a WARNING, skips only the POST probe, runs the read checks,
    and exits 0.
  - The probe now requires exactly 404.

## Decisions
- [ADR 0014](../decisions/0014-seed-job-replaces-upload.md): remove rather
  than protect `/upload` (owner), seed through an opt-in chart Job (owner),
  plain Job rather than a Helm hook.

## Problems and fixes
- **A fresh install used 4 of the original 5 attempts.** The Job got
  `ECONNREFUSED` while the data services started. Fix: `backoffLimit` raised to
  6 and `activeDeadlineSeconds: 900` set.
- **Test harness: `kubectl logs job/` picks an arbitrary Pod.** Fix: the
  harness reads the succeeded Pod.
- **Test harness: `helm upgrade` recreated the deleted NetworkPolicy.** Fix:
  the NetworkPolicy test uses a standalone copy of the Job.
- **Review B1: the digest block list was incomplete.** `backend-image.yml`
  publishes on every `main` push that touches `images/backend/**`. The list
  had three digests, but four pre-#40 images exist. `gh run list
  --workflow=backend-image.yml --branch main` shows four publish runs; each
  publish job log (`containerimage.digest`) and `docker buildx imagetools
  inspect ...:sha-<sha>` agree:

  | Merge | Run | Digest | Pinned |
  | --- | --- | --- | --- |
  | #24 `b65f620` | 36311520545 | `e87390d3...` | yes |
  | #43 `4e7b847` | 41368527221 | `44a87d71...` | yes (#45) |
  | #46 `3925f18` | 42397389747 | `599480a8...` | yes (#48) |
  | #48 `f607f46` | 42494982907 | `f10f726b...` | never |

  #48 changed only `UPSTREAM.md` under `images/backend`, which still
  published an image. Fix: the `seed.js` check is now the primary guard, and
  all four digests are a second guard.
- **Review S2: validation would fail on `main` until the pin deploys.** Fix: a
  pre-#40 image only skips the POST probe, with a WARNING.
- **The runtime reports `imageID` by content, not by the requested name.** On
  `seedtest`, a Pod that requested
  `localhost:5001/thanhdu-hcmus/minishop-backend@sha256:5c9f...` reported
  `imageID` `ghcr.io/thanhdu-hcmus/minishop-backend@sha256:5c9f...`, because
  the same bytes were already present under the ghcr.io name. The imageID check
  alone passed it. Fix: also check the Pod spec image.
- **kubectl jsonpath cannot read the Pod name inside a container range.**
  Fix: a go-template with a `$pod` variable.

## Follow-ups
- Pin PR after merge: take the digest of `sha-<merge sha>` from the
  `backend-image.yml` summary, confirm with `docker buildx imagetools inspect`,
  and update `charts/minishop/values.yaml`, `manifests/20-webapp/backend.yaml`
  (provenance comment) and `deploy/30-platform/hpa-load-test.yaml`.
- Until it deploys, do not enable `seed.enabled`. `validate-app.sh` warns,
  skips the POST probe, and passes on the read checks.
- Owner deploy: back up with `bash scripts/backup-data.sh` (from PR #54),
  deploy with `PATH="$PWD/.tools/bin:$PATH" bash scripts/deploy-helm.sh
  values-dev.yaml`, run `bash scripts/validate-app.sh`; only for an empty
  database, follow the operator guide's "Seeding an empty database" steps
  (local, uncommitted `seed.enabled: true` in `values-dev.yaml`, wait for the
  Job, revert and redeploy).
- Accepted gaps: Job reruns after the 24 h TTL on the next upgrade (idempotent);
  default ServiceAccount without token; a future `data` ingress policy must
  allow the seed Pod; a deliberately emptied table is reseeded if the Job runs.
- Issue #40 parts 3 and 4 (password rotation, data NetworkPolicy) remain.
